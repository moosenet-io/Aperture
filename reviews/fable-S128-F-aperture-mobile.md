Verdict: This is an unusually strong sprint spec — the offline/outbox/conflict trio and the presence-budget push architecture are better thought through than most shipped PWAs — but it has a few real gaps (offline caches not purged on logout, no manifest `id` despite an install-identity migration, iOS storage-partition reality contradicting an acceptance criterion) that should land in the spec before agents fan out.

## ENHANCEMENTS

1. **Manifest `id` field** — APTR-73. Declare an explicit `id` in the manifest. This sprint is literally an install-identity migration away from a legacy manifest (APTR-93); without a stable `id`, install identity is derived from `start_url` and any future path change forks the installed app again. Add a test that `id` is present and relative. **P1**
2. **Purge offline stores on logout / session revocation** — APTR-75 (also 76). Logout and device revocation must clear the IndexedDB thread cache, thumbnails, and outbox (or the stores must be namespaced per user identity). Otherwise the next user of a shared device reads the previous user's threads offline. Add a negative test: logout → offline boot → no thread content readable. **P1**
3. **Per-user store namespacing** — APTR-75. Key every object store by a non-secret user identifier so account switching (or a future multi-account feature) can't cross-contaminate caches or replay another user's outbox. This is also the clean mechanism for enhancement 2. **P1**
4. **Specify how the service worker authenticates `pushsubscriptionchange` re-subscription** — APTR-79. The handler runs in worker context with no page; state explicitly that the BFF session is a cookie the SW fetch inherits, and define the behavior when the session is expired (mark subscription stale, surface re-enable in settings on next open — not a silent permanent loss of push). **P1**
5. **App Badging API tied to the presence budget** — NEW ITEM (or APTR-79). `navigator.setAppBadge()` driven by the same presence decision that authorizes a push (a knock may set/clear the badge; nothing else may). It's the cheapest "the assistant wants you" signal on mobile and costs nothing in quota when a full notification would be too much. Same single-chokepoint rule applies. **P2**
6. **Notification `tag`/collapse semantics** — APTR-79. Define grouping: successive knocks for the same thread collapse (same `tag`) rather than stacking; add `renotify` policy to the push contract. Without this, a flaky reconnect can dump five notifications from one presence decision fan-out. **P2**
7. **Composer draft persistence** — NEW ITEM. Per-thread draft text saved to the offline store on input (debounced), restored on reload/cold start, cleared on send. The outbox saves *sent* messages; drafts are the half-typed message the pull-to-refresh item is protecting — protect it from crashes and tab eviction too. **P1**
8. **Offline search over cached threads** — NEW ITEM. A simple substring/token index over the cached messages in IndexedDB so the thread list is searchable offline. "I know we discussed this on the train" is the canonical mobile-offline moment, and read-only cache without search undersells it. **P2**
9. **`launch_handler: { client_mode: "focus-existing" }`** — APTR-73. Prevent share-target and notification-click launches from spawning duplicate app instances; APTR-79 already does this manually for `notificationclick` — declare it at the manifest level too. **P2**
10. **Manifest completeness: `description`, `lang`, `dir`, `categories`, bundled `screenshots`** — APTR-73. Screenshots make the install sheet dramatically better on the prompt-driven platform; they must be generated at build time from fixtures and bundled (no external host), consistent with clause 6. **P3**
11. **Screen Wake Lock during voice capture** — APTR-80. Acquire a wake lock while recording; a screen that sleeps 30 seconds into a voice memo kills the recording on some platforms. Release on stop/cancel; degrade silently where unsupported. **P2**
12. **`navigator.storage.persist()` + usage display** — APTR-75. Request persistent storage (best-effort, honest about denial) and surface `storage.estimate()` in settings as "Offline data: 38 MB of 60 MB budget", next to the existing "clear offline data" action. Reduces the iOS-eviction edge case and makes the byte ceiling user-legible. **P2**
13. **Respect `Save-Data` / metered hints** — APTR-75, APTR-74. When the data-saver signal is present, skip thumbnail prefetch and background revalidation; document it in the offline contract. Sovereign software that respects the user's data plan is on-brand. **P3**
14. **Use the Web Locks API by name for the outbox single-drainer lock** — APTR-76. The spec says "a single-drainer lock, with the lock expiring"; hand-rolled expiring locks in IndexedDB are a classic source of stuck queues. `navigator.locks.request()` gives crash-releasing exclusivity for free; specify it, with the IndexedDB lease only as the documented fallback. **P2**
15. **Define server-side idempotency-key retention** — APTR-76 (BFF sibling PR). The dedup guarantee is only as strong as how long the BFF remembers keys. State a retention window (e.g., ≥ the max outbox age) in `contracts/aperture-offline-v1.md`, and define what happens when a replay arrives after expiry (treat as `diverged`, prompt — fail closed, never silently duplicate). **P1**
16. **Interleaving rule: live sends vs. draining queue** — APTR-76. The user reconnects, the drain starts, and they type a *new* message into the same thread mid-drain. Specify: the new message enqueues behind the queued ones in that thread's serial drain, so thread order equals compose order. Add a unit test. **P2**
17. **Concretize `superseded` detection** — APTR-77. "Semantically-overlapping message from another client" is hand-waving — nobody can implement or test "semantically." Define it mechanically: same user, message sent to the same thread within the queued message's offline window, and let the *prompt copy* (or the assistant) do the semantic judgment. Rewrite the contract line so the detection is deterministic. **P1**
18. **Server-time provenance for composed-at** — APTR-77. Device clocks are wrong often enough that composed-at from wall clock will occasionally postdate delivered-at. Record composed-at as (local wall clock + monotonic sequence + last-known server-time offset) and let the BFF normalize; the assistant reasoning about the delay needs a timestamp it can trust. **P3**
19. **SSE resume semantics on mobile radio churn** — NEW ITEM (or APTR-75). Mobile networks flap constantly; a stream that dies mid-response should resume via `Last-Event-ID` (or the Sprint B equivalent) rather than restarting the turn or losing tokens. If Sprint B already carries resume tokens, add the mobile test here: kill connectivity mid-stream, restore, assert the response completes without duplication. **P1**
20. **Explicit SW kill-switch mechanism** — APTR-74. "A documented kill switch" needs a shape: a query parameter or settings toggle that unregisters the worker and clears its caches, plus `Cache-Control: no-store` on the SW script itself so a bad worker can always be replaced within one navigation. Specify and test it — this is the escape hatch for the "can brick every installed client" risk the item itself names. **P1**
21. **Diagnostics export (user-initiated, no telemetry)** — NEW ITEM. A settings action that copies a redacted local diagnostic bundle (build id, SW state, cache versions, outbox depth, capability matrix results — no message content, no tokens, no hostnames) to the clipboard. With zero telemetry by design, this is the *only* way a mobile bug report ever contains enough to act on, and it keeps sovereignty intact because the user carries it. **P2**
22. **Passkey/platform-authenticator re-auth on mobile** — NEW ITEM (depends on Sprint B). Session expiry on a phone plus a password form is where daily-driver usage dies. Offer WebAuthn platform-authenticator (Face/fingerprint) re-auth against the existing device record, so the outbox re-auth halt in APTR-76 resolves in two seconds instead of a password hunt. **P2**
23. **Lock-screen content default** — APTR-79. The spec mentions a "hide content on lock screen" setting but not its default. State it: default to hiding assistant text on the lock screen (content-free knock), opt into full content. Private-by-default is clause 6's spirit applied to a train seat. **P2**
24. **Shortcut icons and offline shortcut behavior** — APTR-73. `shortcuts` entries need their own bundled icons (add to the gen-icons matrix), and "Continue last thread" invoked offline must land on the cached thread, not a spinner — add that route to APTR-75's surface-enumeration test. **P3**
25. **Pending-share payload expiry** — APTR-80. A share held because the user was logged out sits in IndexedDB indefinitely. Give held shares a TTL and byte cap, and surface them ("you have an unsent share") rather than letting them rot or leak into a later session. **P2**
26. **Replace TTI with INP/LCP-class lab metrics** — APTR-81. TTI is deprecated in current tooling and increasingly unmeasurable; specify LCP plus a scripted-interaction latency (INP-style) on the throttled profile instead, keeping the same median-of-N fail-closed discipline. Same intent, measurable for the next five years. **P2**

## DEFECTS

- **APTR-73 / APTR-75 (iOS session continuity):** the edge case "a user who installs… must land in their existing session" is not achievable as written on the promptless platform — installed PWAs there get a **separate storage partition** from the browser (cookies and IndexedDB do not carry over). The honest behavior is: install → re-authenticate once → server-side memory/traits/lore intact. The acceptance criterion should say that explicitly, and APTR-82's matrix must document it, or testers will file the platform as a bug.
- **APTR-77 (`superseded`):** "semantically-overlapping" is untestable hand-waving — see enhancement 17. As written, neither the detection code nor its unit test can be built to the contract.
- **APTR-79 ("exactly one caller" test):** asserting a Rust function has exactly one caller is not a unit test; it's static analysis. Specify the mechanism — module-private visibility so the compiler enforces it, plus a CI grep/AST check for the symbol outside the presence module — or the acceptance criterion is unverifiable as stated.
- **APTR-93 (unregistration window):** with zero telemetry there is no signal for when the window may close; the spec defers the length to the PR body. It should be fixed in-spec as time-based and generous (≥ 30 days — browsers recheck SW scripts at most every 24h but only on navigation, and dormant installs navigate rarely), and require `Cache-Control: no-store` on the transitional worker script so the legacy worker actually picks it up.
- **Sprint metadata:** the estimate says "~69h across 11 items" but the per-item estimates sum to **76h** (6+8+8+8+7+8+8+6+7+5+5). Minor, but agents budget against this line.
- **APTR-75 (offline boot identity):** "never store a session token" is correct, but then an offline cold start can only render authenticated cached content if the session lives in an HttpOnly cookie (unavailable offline for validation) — the spec silently depends on Sprint B's session shape. State the dependency: offline boot trusts a non-secret local "last authenticated user" marker for rendering cached data, and full validation happens on reconnect.

## MISSING

- **Logout/revocation purge of offline data** (defect-grade omission; enhancements 2–3). Nothing in APTR-75/76 clears caches or the outbox when the session ends or the device is revoked. This is the sprint's biggest privacy hole.
- **Drafts.** The half-typed message is defended against pull-to-refresh (APTR-78) but not against a crash, tab eviction, or OS killing the PWA — no draft persistence exists anywhere (enhancement 7).
- **Local-data-at-rest threat model.** Cached threads and queued message text sit in plaintext IndexedDB. That may be an acceptable tradeoff (device encryption is the OS's job), but the decision should be written down in `contracts/aperture-offline-v1.md`, not left implicit.
- **i18n/RTL posture.** Push bodies, offline copy, and the conflict prompts are all user-facing prose; not one item mentions locale or RTL layout (safe-area work in APTR-78 interacts with RTL). Even "English-only for v0.1, strings centralized" would do.
- **Mobile SSE resume** (enhancement 19) — the single most common mobile failure mode (radio handoff mid-stream) has no item and no test in this sprint.
- **WebKit-engine test coverage.** The test-device list covers install models but the CI plan never says the headless integration suite runs on a WebKit engine, which is where most PWA behavior diverges. Add it to APTR-81's CI jobs or Sprint G inherits the gap.
- **Badging, wake lock, storage-persist, Save-Data** — small platform affordances (enhancements 5, 11, 12, 13) that separate "installable web page" from "app."
