Verdict: A genuinely strong sprint spec — the security posture, negative tests, and Soul Contract discipline are well above the norm — but it ships to autonomous agents with at least one real cross-item contradiction (attachment lifecycle vs. branching), an unstated CSRF story on a sprint that adds dozens of mutating routes, and a handful of ambiguities that fanned-out agents will resolve divergently. Fix those, take the enhancements, and this is excellent.

## ENHANCEMENTS

1. **Tool-result voice containment (anti-impersonation)** — APTR-36. A tool result rendered through the markdown pipeline can contain content *styled* to look like an assistant message (a blockquote mimicking a bubble, "Assistant:" prefixes, headings that read as speech). Sanitization stops script execution but not visual impersonation. Require: tool results render inside a visually bounded, labelled frame that markdown inside it cannot escape; message role/provenance comes only from the server-side event envelope, never inferred from content; add a negative test feeding a tool result crafted to mimic an assistant bubble and asserting it stays inside the frame with tool provenance visible. This is the prompt-injection-surfacing test the sprint currently lacks. **P1**
2. **Confirmation gate for mutating tools** — APTR-36 + APTR-31. The mutation flag is shown *after* the fact. Add a per-workspace setting "require approval for state-changing tools": a mutating tool call renders as a pending approval block (approve / deny / always-allow-this-tool), enforced in the BFF before dispatch through the door. In a fleet where the assistant touches real infrastructure, retrospective provenance is not enough. **P1**
3. **Attachment reference counting across branches** — APTR-35 + APTR-32 + APTR-31. Define attachment ownership explicitly: attachments are workspace-owned objects with reference counts; thread delete removes references, storage is reclaimed only at zero references; workspace hard-delete reclaims all. This resolves the current contradiction (see DEFECTS #1) and needs a test: delete origin thread, assert branch still renders its attachments. **P1**
4. **CSRF posture stated and tested** — NEW ITEM (or pre-flight constraint). Sprint C adds workspace/thread/message/attachment/admin mutation routes. If sessions are cookie-borne, every one is CSRF-able. Require: SameSite=Strict/Lax + origin-check middleware on all non-GET BFF routes (or a token scheme), with a contract-enumerated test that every mutating route rejects a cross-origin request — same style as APTR-44's enumerated authz test. **P1**
5. **Session-expiry-mid-stream recovery** — APTR-33 + NEW. Define what happens when the session expires or is revoked during an active SSE stream and during an upload: a typed auth error, the partial message preserved and marked, re-auth without losing the thread state or composer draft, stream resumable after re-auth. Currently only the admin-deactivation case (APTR-44) covers stream termination. **P1**
6. **Sign-out device hygiene** — APTR-42 + APTR-33. Per-thread drafts, palette recency, and layout state live in device-local storage. Drafts are user content. Sign-out (and remote device revoke, when the revoked device next connects) must purge drafts and any cached message content; add a test asserting local storage contains no thread content after sign-out. **P1**
7. **Sandboxed attachment-preview origin, mandated not "documented"** — APTR-39. Item 6 says "document the isolation approach chosen." Don't leave it open: mandate either a dedicated sandbox origin/subdomain or `Content-Security-Policy: sandbox` on every preview response, and add a test asserting a served HTML/SVG attachment cannot execute script or reach the app origin's cookies. This is exactly the "second access path around the door" class the review criteria call out. **P1**
8. **EXIF/metadata stripping on images** — APTR-39. Uploaded photos carry GPS and device metadata; a screenshot paste carries less but re-served images should still be scrubbed. Strip EXIF/XMP server-side on ingest for image types; test with a GPS-tagged fixture. **P2**
9. **Universal jump in the command palette** — APTR-30. The palette currently searches commands only. Make it the universal switcher: fuzzy search over threads (title + recent), workspaces, documents, and memory items alongside commands, with typed prefixes (`>` commands, `#` threads, `@` docs). Thread/doc lookup goes through the existing server-side search route, debounced — this is the single biggest daily-driver delight win in the sprint. **P2**
10. **Search-result jump-to-message and in-thread find** — APTR-32 + APTR-33. Results carry offsets but nothing says clicking one opens the thread *scrolled to the matched message, highlighted*. Also, virtualization breaks browser Ctrl+F silently — ship an in-thread find (bound to Ctrl+F or discoverable) that searches the full thread server-side and navigates matches. Without this, virtualization is a usability regression nobody will file correctly. **P2**
11. **Message permalinks, timestamps, day separators** — APTR-33. Each message gets a stable deep-linkable URL (thread + message id, access-checked like everything else), hover/focus timestamps with absolute time, and day separators in the list. APTR-41 already gives memory items stable URLs; messages deserve the same so the assistant and users can cite them. **P2**
12. **Thread and workspace export** — NEW ITEM. A sovereign system with no data-out is a contradiction. Export a thread as Markdown/JSON and a workspace (threads + document manifest) as an archive, generated server-side through the BFF, access-checked, with reasoning excluded by default (consistent with APTR-37 copy semantics). **P2**
13. **First-run and invited-user onboarding** — NEW ITEM. Sprint C's exit criterion narrates an invited user's first session but no item owns it: first sign-in lands on a guided flow (create/join workspace, meet the assistant — with the introduction authored via the persona assembler per Soul Contract clause 1, not templated by Aperture), and the empty app states from APTR-46 link into it. **P2**
14. **Resolve the unread-state tension** — APTR-43 + APTR-32. "No unread badge anywhere" as written makes the thread sidebar amnesiac: a reply that arrived while you were elsewhere is invisible. Distinguish *interruptions* (budget-governed, correctly banned) from *passive navigational state* (a quiet unread dot on a thread row, no count, no sound, no focus steal). State the distinction in `docs/PRESENCE.md` and adjust the negative test so it bans counters/toasts, not the dot. **P2**
15. **Rate limiting on user-driven expensive routes** — NEW ITEM / APTR-32, APTR-38. Invites are rate-limited; nothing else is. Message send, server-side search, title suggestion (an LLM call per invocation!), re-embed, and upload initiation all need per-principal rate limits at the BFF with typed `rate-limited` problem-details the APTR-46 vocabulary can render. **P2**
16. **Upload-session protocol made explicit** — APTR-38. "Chunked and resumable" hides a protocol: chunk-session creation route, chunk size, session expiry, and garbage collection of abandoned sessions (which is also a storage-exhaustion vector APTR-39 should count against quota). Put the routes in the contract and add a test that an abandoned session is reaped and its bytes released. **P2**
17. **Streaming performance as a CI assertion, not a claim** — APTR-33. "60fps" appears only in prose. Add a benchmark test: stream N tokens into a 500-message thread and assert frame time / commit count against a budget in CI, so the render-count test isn't the only guard on the sprint's central performance promise. **P2**
18. **In-app shortcut cheat sheet** — APTR-30. `?` (scope-aware, not in inputs) opens an overlay generated from the command registry — the same source as `docs/KEYBOARD.md`, so it can't drift. Discoverability in-app beats a doc file. **P3**
19. **Queue-next-message instead of hard-disabling the composer** — APTR-33. Let the user finish typing and queue one message to send on stream completion, with a visible "queued" chip and cancel. Hard-disabling send mid-stream punishes exactly the fast users this spec says it serves. **P3**
20. **Paste-large-text-as-attachment** — APTR-38. Pasting thousands of lines into the composer should offer conversion to a text attachment (routed through the normal pipeline) rather than creating an unscrollable bubble and a megabyte turn payload. **P3**
21. **Voice dictation via the door** — NEW ITEM, APTR-33 composer. Chord already serves `/v1/audio/*`; add push-to-talk dictation: capture locally, transcribe through the BFF by named proxy, insert into the composer. Fully sovereign, no external service, and a genuine mobile/desktop delight ahead of Sprint F. **P3**
22. **Remote-image click-to-load: sharpen the policy** — APTR-34. On click, the fetch goes direct from the user's browser to a remote origin — an IP/UA leak the constraint set otherwise forbids. Show the full origin before load, remember per-origin consent per device, and explicitly document in the spec that this is the sanctioned carve-out to constraint 3 (and that a BFF media proxy was rejected as an SSRF surface). Right now the constraint and the feature contradict each other silently. **P2**
23. **Storage quota visibility** — APTR-40/APTR-42. APTR-39 enforces per-user quotas; no surface shows them. Add usage/quota to the document manager and account settings so "quota exceeded" is never the first time a user learns quotas exist. **P3**
24. **Admin audit-log viewer** — APTR-44. Audit entries are written but nothing reads them. A filterable, paginated audit view (actor, action, target, time, correlation id) on the admin surface, read-only, same authorization middleware. **P2**
25. **Invite token delivery hygiene** — APTR-44. Specify the redemption URL carries the token in the fragment (not path/query) so it never lands in server logs, referrers, or history-sync; one-click copy with confirmation; redemption page sends no referrer. **P2**
26. **Scroll-position and context restoration per thread** — APTR-33. Reopening a thread restores where you were (or jumps to newest with a "you were here" marker), persisted per device. Small, and the difference between a tool and a toy for long-lived threads. **P3**

## DEFECTS

1. **APTR-32 vs APTR-35 — attachment lifecycle contradiction.** APTR-32 says thread delete "is scoped to the thread's messages and attachments"; APTR-35 says branches reference (not copy) attachments and "deleting the origin thread must not orphan the branch's view of them." Both cannot hold as written. Two agents implementing these items independently will build incompatible semantics. Fix per Enhancement 3 before fan-out.
2. **APTR-31 — "last-write-wins with an `updated_at` precondition" is self-contradictory.** A precondition that returns a conflict on stale write is optimistic concurrency control, the opposite of last-write-wins. Same phrase pattern risk in APTR-42's "two devices changing appearance concurrently — last write wins." Pick one model per surface and name it correctly.
3. **APTR-42 — missing dependency.** The avatar upload is "routed through the hardened attachment path (APTR-39)" but APTR-42 declares no `Blocked by`. It needs at least APTR-38/39, or the avatar path must be explicitly deferred.
4. **APTR-46 — dependency metadata contradicts the sequencing prose.** The item says it is "sequenced last so the check runs against every surface" but declares only `Blocked by: APTR-33`. Under the epic's "items are independent unless Blocked by says otherwise" rule, an agent may legitimately start it before APTR-40/41/44 exist. Block on all surface-introducing items or on the sprint's merge order explicitly.
5. **APTR-33 — "submission is disabled while a stream is active" is under-scoped.** Per app? Per workspace? Per thread? A stream in thread A must not lock the composer in thread B (the rapid-thread-switch edge case implies per-thread, but the constraint as written implies global). State the scope.
6. **APTR-36 — "cancellable if the backend supports it" is a hand-wave.** No descriptor field, contract route, or event for tool-call cancellation is defined anywhere in the sprint. Either specify the capability flag and cancel route in the contract or strike the claim.
7. **APTR-43 lint vs. error surfacing.** `lint-presence.mjs` bans "toast-raising helpers" outside PresenceClient, but APTR-30 says a throwing command "surfaces a typed error" and APTR-46 needs transient error feedback. Define which transient-feedback mechanisms are errors (permitted, product voice) vs. interruptions (banned), or the lint will either be evaded or block legitimate error UX.
8. **APTR-34 constraint conflict (silent).** Click-to-load remote images performs a runtime external fetch, which standing constraint 3 flatly forbids. The carve-out may be the right call, but it must be written down as a carve-out with its rationale (see Enhancement 22), not left as a latent contradiction for the Sprint G security review to trip over.

## MISSING

- **CSRF and the cookie/session transport model for Sprint C's mutating routes** — entirely absent (Enhancement 4). The sprint's biggest unstated security assumption.
- **Multi-tab behavior.** Two tabs on the same session: does each open its own SSE connection? Are context-bus events (thread focus) emitted twice, confusing the assistant about "where the user is"? Do drafts conflict? Needs a stated model (shared connection or server-side dedupe) — nothing in the sprint acknowledges more than one tab exists.
- **Pre-Aperture history.** A user who has conversed via Matrix for a year opens Aperture to an empty thread list. Memory survives (clause 4), but the *transcript* continuity story — whether Matrix history surfaces in Aperture, or an explicit statement that it does not and why — is unaddressed. First-run will feel like amnesia even though it isn't.
- **Data export / portability** (Enhancement 12) — no way to get content out of a sovereign system.
- **First-run/onboarding** as an owned item (Enhancement 13) — the exit-criteria journey has no author.
- **Rate limiting** on send, search, title-suggestion, and re-embed (Enhancement 15) — the abuse story stops at uploads and invites.
- **String centralization / i18n posture.** Even if English-only is the decision, say so and centralize user-facing strings now; retrofitting extraction across 18 items' worth of copy later is miserable.
- **Locale/time formatting rules.** Date bucketing, quiet-hours timezones, and timestamps all touch locale; no shared utility or convention is named.
- **BFF-side backup/restore expectations** for workspaces, threads, and attachments — even one sentence pointing at where that responsibility lives (agent-core ops, not Aperture) would prevent the assumption it's handled.
- **Upload-session garbage collection** (Enhancement 16) — a storage-exhaustion gap in an otherwise thorough APTR-39 threat model.
