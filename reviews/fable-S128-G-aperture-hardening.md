Verdict: This is an unusually strong hardening sprint — the deterministic fake, fail-closed gates, and the stub-deploy assertion show real scar tissue — but several acceptance criteria are self-contradictory as written (the verify harness cannot be both "public contract only" and assert internal state; several subcommands cannot meaningfully run against the fake), and the desktop-origin auth/CSP problem is hidden behind one confident clause. Fix those and this ships.

## ENHANCEMENTS

1. **Desktop auth design made explicit** — APTR-84. `SameSite=Strict` cookies + `connect-src 'self'` CSP is structurally incompatible with a Tauri shell (custom scheme origin) talking to a remote BFF. Add an explicit design section: desktop uses a bearer session token in OS-keychain-backed storage, never cookies; the CSP for the desktop webview gets its own written policy with the BFF origin in `connect-src`; the threat model gets a "desktop origin" boundary. **P1**
2. **Service-worker update lifecycle assertion** — APTR-89. The post-deploy served-bundle assertion checks the server, but installed PWAs serve from SW cache and can present a stale (or stub-era) bundle indefinitely. Add: SW versioned by bundle hash, an "update available — reload" affordance, an e2e journey asserting a new deploy propagates to an already-installed PWA within a bound, and a `aperture-verify sw-version-current` subcommand. **P1**
3. **Chaos scenario: BFF restart mid-stream** — APTR-87. Kill and restart the BFF (kernel faked) while N streams are open; assert clients reconnect with jittered backoff, resume or receive explicit `resync required`, and no client silently shows a truncated thread. Restart is the most common real-world event and no scenario covers it. **P1**
4. **Rolling-deploy contract skew test** — APTR-89. During deploy/rollback, an old cached client bundle will talk to a new BFF (and vice versa after rollback). Assert the contract's versioning handles one-version skew gracefully: typed `contract-version-mismatch` problem-details plus a client-side "please reload" state, never a parse crash. Pairs with the rollback criterion, which currently only re-runs the hash assertion. **P1**
5. **Auth abuse hardening** — APTR-84. The threat model covers session mechanics but not credential attack: add rate limiting + progressive backoff on login and device-link endpoints, generic error bodies (no user-enumeration oracle), a local audit log of auth events (login, failure, revocation, elevation), and negative tests for each. **P1**
6. **Supply-chain gate** — NEW ITEM. This repo ships publicly and pins dependencies, but nothing audits them: add a CI job running offline-mirrored `npm audit`/`cargo audit`, a lockfile-integrity assertion (install fails on lockfile drift), SBOM generation attached to release artifacts, and a secret-scanning pass gating both CI and the pre-mirror-push. The `assert-no-telemetry` bundle check catches runtime egress but not a compromised build-time dependency. **P1**
7. **`security-headers` and `csp-strict` verify subcommands** — APTR-94. The catalogue has no subcommand asserting the CSP, `frame-ancestors`, HSTS, and anti-buffering headers on a live deployment — the exact thing an operator needs post-deploy and the runbook's "tokens arrive in a burst" symptom check. **P1**
8. **Share-target as an injection surface** — APTR-84. Sprint F's share-target receives attacker-choosable URLs and text that land directly in the composer/upload path. Add it as a named trust boundary with tests: shared `javascript:`/`data:` URLs neutralized, shared text never auto-submitted, deep links from shares never trigger state-changing actions. **P1**
9. **Sanitizer fuzzing** — APTR-84. The hostile corpus is static; add a fuzz job (mutational, seeded from the corpus) run nightly against the sanitize chokepoint, with any crash or sanitizer-bypass minimized into a new corpus entry. A fixed corpus decays; a fuzzer compounds. **P2**
10. **Trusted Types as a second rampart** — APTR-84. Add `require-trusted-types-for 'script'` to the CSP and a default policy that throws. This makes "raw HTML injection outside the chokepoint" a runtime impossibility in supporting browsers, not just a lint rule. **P2**
11. **Local CSP violation reporting** — APTR-88. Wire `report-to` to a same-origin BFF endpoint feeding the local metrics (`csp_violation_total` by directive). A violation in production is the earliest possible signal of a sanitizer bypass, and today it would be invisible. **P2**
12. **Correlation id surfaced in the error UI** — APTR-88. The runbook says "read a correlation id off an error surface" but no item makes the client render it. Add: every typed error state shows the id with a copy button; the support bundle indexes by it. **P2**
13. **Symptom → subcommand table in the runbook** — APTR-90. Every symptom-indexed procedure should open with the one `aperture-verify` invocation that discriminates it (e.g., blank app → `sw-version-current` + the served-bundle assertion; burst tokens → `stream-headers`). Plus an `aperture-verify doctor` meta-subcommand running the incident-triage subset in order. **P2**
14. **Interaction-latency and scroll-jank budgets** — APTR-85. The four budgets miss the two things a user feels most in a long thread: keypress→echo latency in the composer and frame time while scrolling a 1,000-message virtualized thread. Add both, measured against the fake's scripted long transcript. **P2**
15. **Multi-session concurrency journey** — APTR-83. Same account in two tabs/devices: send from one, assert the other observes it via SSE; revoke one device from the other and assert the revoked one's stream dies while the surviving one is unharmed. This is the flow real households hit first and nothing covers it. **P2**
16. **Mobile assistive-tech and forced-colors pass** — APTR-86. The manual pass is desktop screen-reader shaped. Add VoiceOver (iOS PWA) and TalkBack passes over the core flows, and a Windows forced-colors/high-contrast mode check — the design-token contrast audit does not cover forced-colors, where the OS discards your palette. **P2**
17. **Client-side persisted-state migration** — NEW ITEM (pairs with APTR-89 rollback). Local state (drafts, offline queue, settings, SW caches) needs a schema version; assert an *older* bundle after rollback either migrates down or fails closed to a clean re-fetch — never a crash-loop on unrecognized state. Rollback is currently only tested server-side. **P1**
18. **Visual regression snapshots in e2e** — APTR-83. Screenshot-diff the provenance chrome, tool-result framing, error states, and both themes against checked-in goldens. The non-forgeable speaker chrome is a *visual* guarantee; a CSS regression that makes tool-result chrome look like assistant chrome passes every structural test and defeats the whole point. **P2**
19. **Hostile-corpus governance** — APTR-84. Name the corpus a living artifact: location, how a new bypass class gets added, and a rule that every security finding from the capstone or a review lands as a corpus entry before its fix merges. Otherwise the corpus fossilizes at v0.1.0's threat imagination. **P2**
20. **Quarantine aging visibility** — APTR-83. "At most one merge" needs a mechanism: the quarantine list is a checked-in file with the quarantining PR id, and CI fails when a quarantined journey survives more than one subsequent merge to `main`. Right now enforcement exists only at capstone time, months after the shrug. **P2**
21. **Clock-skew cases** — APTR-84/APTR-87. Session expiry evaluated server-side only (a skewed client must not self-log-out or trust its own clock), and `Retry-After` honored as a duration, not an absolute time. One negative test each. **P3**
22. **Bidi/RTL content smoke** — APTR-83. Messages containing RTL text and Unicode bidi-override characters render without reordering surrounding UI or spoofing filenames/URLs in the provenance chrome (the filename neutralization covers uploads but not message content). **P3**
23. **Desktop cold-start budget** — APTR-85. Add Tauri launch→interactive and PWA offline-shell paint to `perf/budgets.json`; first paint of the web target doesn't capture either shipped experience. **P3**
24. **Machine-readable capstone findings artifact** — APTR-92. Alongside `docs/EPIC-REVIEW.md`, emit `epic-review-findings.json` (finding, panelist, disposition, issue id) so the "every finding triaged" criterion is asserted by a script, not by a reader trusting prose. **P3**
25. **Export-thread-as-Markdown affordance** — NEW ITEM (small, delightful). A user-initiated, local-only export of a thread (with provenance labels preserved as blockquote framing) covers the support-bundle "show me what happened" case *and* is the kind of sovereignty-affirming feature this project's audience will love. **P3**

## DEFECTS

1. **APTR-94** — Approach §1 ("uses only the public contract... an implementation that reaches around the contract is a rejection") directly contradicts the catalogue: `assert-no-default-signing-key`, `state-file-has-no-secret`, `desktop-binary-unchanged`, `registry-entry-reaped`, `handles-flat-over-soak`, and `env-example-matches-code-keys` all require host/filesystem/internal access. As written, a correct implementation of §1 makes those subcommands unimplementable. Tier the catalogue explicitly: contract-mode checks vs. host-mode checks, with the "no privileged backend path" rule applying to contract-mode only.
2. **APTR-94 / APTR-83** — "Every subcommand runs against both the deterministic fake and a live deployment; a subcommand that only works against one of the two is a defect" cannot hold for `continuity-preserved`, `memory-present-after-channel-add`, `quiet-hours-honored`, or `traits-present-after-revocation-cycle`: the fake has no Engram, no traits, no presence budget. Against the fake these test fixtures replaying themselves — a fiction. Declare a live-only subset, and make the continuity clause's real verification a live post-deploy check.
3. **APTR-84** — The desktop/PWA origin problem (Defect 1's substance) is dispatched in one sentence ("handled explicitly") while the same item mandates `connect-src` same-origin and `SameSite=Strict`. Those three statements cannot all be true for the Tauri target. This is the classic hidden hard problem the review criteria ask me to flag.
4. **APTR-84** — CSRF, session fixation, CSP, and header fixes live in an agent-core "sibling PR", but this item's acceptance criteria assert them and its tests must exercise them. Merge ordering, cross-repo CI, and which repo owns the negative tests are unspecified; as written, this repo's CI can go green with the sibling PR unmerged.
5. **APTR-83** — Desktop journeys "run against the packaged artifact" in a *required* CI job, which implies signing prerequisites (Apple notarization, Windows cert) on the CI runner — a real security and feasibility problem the spec doesn't acknowledge. Define an unsigned-but-identically-packaged CI artifact variant and state explicitly that signing itself is verified in the Sprint E release path, not per-PR.
6. **APTR-89** — The served-bundle assertion is defeated for actual users by the PWA service worker cache (Enhancement 2). The item's own motivating war story — "every dashboard green, users see nothing" — can recur through this exact path with every check in the item passing.
7. **APTR-85** — "force collection" is not possible in a stock browser context; heap measurement needs an instrumented run (CDP `HeapProfiler.collectGarbage` or `--expose-gc`). Unspecified, this is the first flaky gate in the sprint. Name the mechanism.
8. **APTR-92** — Negative test "confirm the doc engine did NOT fire on any per-merge step anywhere in the epic" is untestable retroactively unless an audit trail of doc-engine invocations exists; no item creates one. Specify the evidence source or the criterion is prose.
9. **APTR-91** — Blocked only by APTR-84, yet Approach §5 requires listing "defects the panels missed and were caught later by a test, a soak, or a deploy assertion" — evidence produced by APTR-83/85/87/89. It should be blocked by all of them, or the retrospective's most valuable section will be written before its inputs exist.
10. **APTR-88** — "Metrics endpoint... covered by the same session/authorization rules as every other route" conflicts with its consumer: a scraper has no interactive user session. Needs its own stated authn (internal bind + static bearer from the vault), or the criterion will be "fixed" ad hoc at deploy time.

## MISSING

- **Supply-chain and secret-scanning gates** (Enhancement 6) — the largest absent category for a publicly mirrored, dependency-pinned repo.
- **License audit for the public mirror** — nothing verifies bundled dependencies' licenses are compatible with public publication; one AGPL transitive dependency makes the mirror a liability.
- **Client-side state migration/rollback** (Enhancement 17) — rollback is tested server-side only; the client's persisted state after a rollback is nobody's item.
- **Service-worker cache invalidation** (Enhancement 2 / Defect 6).
- **Auth abuse resistance** (Enhancement 5) — rate limits, enumeration resistance, auth audit log.
- **A supported-platform matrix** — no item declares which browsers/OS versions the e2e matrix represents and which are best-effort; "PWA on iOS" hides significant capability variance (push, install, storage eviction) that the mobile journeys will hit undeclared.
- **Mobile storage eviction** — iOS evicts PWA storage under pressure; the offline queue and drafts need a defined loss-or-survive contract and a journey for it.
- **Incident severity taxonomy** — the runbook escalates "anything requiring a human" but never defines severities or what constitutes user-facing-down vs. degraded, which is what a 2am reader triages by.
- **Fuzzing** (Enhancement 9) and **forced-colors/mobile AT audits** (Enhancement 16).
- **An explicit CORS statement** — the BFF's CORS policy (presumably: no CORS at all, same-origin only, desktop excepted via its own mechanism) is implied everywhere and written nowhere; it belongs in the threat model as a named decision.
