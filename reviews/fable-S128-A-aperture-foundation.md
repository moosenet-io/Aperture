Strong foundation sprint with real mechanical enforcement, but the v1 contract (APTR-06) leaves out the exact things contract-first exists to prevent churn on — auth cookie/CSRF semantics, SSE provenance, desktop base-URL reality, and upload-serving isolation — and two enforcement scripts have correctness bugs as written.

## ENHANCEMENTS

1. **SSE event provenance field** — APTR-06 — Add a mandatory `origin` discriminator (`assistant | tool | system | user`) to every SSE event and every message object, and state in the contract that clients MUST derive visual voice/attribution from `origin`, never from content. This is the contract-level backbone of "a tool result must never impersonate the assistant"; if it's not in v1, Sprint C invents it ad hoc. **P1**
2. **Session cookie and CSRF spec in the contract** — APTR-06 — The `auth` route group is defined but the session mechanics aren't. Specify: `__Host-` prefixed cookie, `HttpOnly`, `Secure`, `SameSite=Strict`; session ID rotation on login (fixation defense); Origin/Sec-Fetch-Site checking on all mutating routes; explicit "no CORS headers ever on `/v1/aperture/*`". Sprint B coding this without a contract is exactly the churn this sprint exists to prevent. **P1**
3. **Desktop transport contract** — APTR-06/APTR-07 — "Never construct an absolute URL" is impossible for Tauri: the desktop app's origin is `tauri://localhost` (or a custom scheme), so `/v1/aperture/...` does not resolve to the fleet. The SDK needs an injectable base-URL transport (default: same-origin; desktop: operator-configured endpoint stored in Tauri secure storage), and the contract needs to say what auth looks like cross-origin (bearer, not cookie). Define it now or Sprint E breaks a Sprint A acceptance criterion. **P1**
4. **Typed SSE client in the SDK** — APTR-07 — Generate a discriminated-union event type from the APTR-06 enum and ship one `ApertureStream` wrapper handling `Last-Event-ID` resume, heartbeat-timeout detection, and backoff. Otherwise Sprints B–D each hand-roll EventSource handling. **P1**
5. **SSE replay-window semantics** — APTR-06 — `Last-Event-ID` resume is named but unbounded. Specify the retention window (e.g., N events or T seconds per stream), and a `resync` event the server emits when the client's ID has fallen out of the window, telling the client to refetch thread state via REST. Without this, resume is a confident sentence hiding a hard problem. **P1**
6. **Attachment serving isolation** — APTR-06 — The contract defines upload but not serving. Mandate: user uploads served with `Content-Disposition: attachment` or from a sandboxed path with a restrictive per-response CSP (`sandbox`), server-side MIME sniffing, an explicit MIME allowlist, and SVG/HTML never served inline. This kills stored XSS via uploaded SVG before Sprint C exists. **P1**
7. **CSP and security headers item** — NEW ITEM — The `assert-no-external-hosts` grep is static and bypassable by string concatenation. Add a BFF-served CSP for the web bundle: `default-src 'none'; script-src 'self'; connect-src 'self'; img-src 'self' blob:; style-src 'self'; frame-ancestors 'none'`, plus `X-Content-Type-Options`, `Referrer-Policy: no-referrer`, COOP/COEP. This is the runtime enforcement of clause 6; the grep is only advisory. **P1**
8. **Idempotency keys for message send** — APTR-06 — A network blip during a POST-and-retry double-sends a message. Add an `Idempotency-Key` header contract for message create (and later, actions), with server-side dedupe semantics. **P1**
9. **Client↔BFF version-skew handling** — APTR-06 — A cached PWA bundle (Sprint F) will outlive BFF deploys. Add a contract version header on every response and a defined client behavior on mismatch (soft-reload prompt, not silent breakage). Cheap now, painful to retrofit. **P1**
10. **Secret-cache properties** — APTR-11 — "Fall back to cached vault values" doesn't say where the cache lives or how it's protected. Specify: memory-only or encrypted-at-rest, zeroize-on-drop, TTL, and behavior when the cache is also cold (capability `unavailable`). **P1**
11. **Command palette + shortcut registry scaffold** — NEW ITEM — Add a foundation-level command registry (`registerCommand(id, title, keywords, handler)`) and a `Cmd/Ctrl-K` palette with fuzzy search, so every later sprint registers threads, module actions, and settings into one surface instead of retrofitting in Sprint G. This is the single highest-leverage delight feature and it must be architectural to work. **P2**
12. **Pagination and concurrency conventions** — APTR-06 — Define cursor pagination shape, sort/filter query conventions, and ETag/`If-Match` optimistic concurrency for thread/settings mutation once, in the contract README. Add `conflict` and `precondition-failed` to the APTR-10 URN taxonomy. **P2**
13. **Health/readiness/version routes** — APTR-06 — Add `GET /v1/aperture/health` (liveness) and a version endpoint returning contract version only — explicitly no build hashes, hostnames, or upstream component versions (infrastructure-leak rule applies to health endpoints too, and specs rarely say so). **P2**
14. **Automated contrast + reduced-motion in CI** — APTR-02 — The 4.5:1 check is described but not mechanized. Add a script that parses `constellation.css`, computes contrast for every declared fg/bg token pair in both themes, and fails CI on violation. Also add `prefers-reduced-motion` token behavior and `forced-colors` support now. **P2**
15. **Self-hosted component gallery + visual regression** — APTR-02 — A `/dev/gallery` route (stripped from prod builds) rendering every primitive in both themes, screenshot-compared in CI via Playwright. Gives the design system a real negative test — currently "primitives render" tests would not catch a broken dark theme. **P2**
16. **Error boundary and presence-budget-safe toast primitive** — NEW ITEM — A typed top-level React error boundary (renders a design-system fallback, reports via the correlation-id pipeline) and one toast/inline-notice primitive that Sprint C+ must use, documented as render-only so nobody builds a second notification channel around the Soul Contract clause 2 budget. **P2**
17. **Threat model document** — NEW ITEM — A short STRIDE pass over the BFF surface (auth, stream, attachments, events) written in Sprint A, so the Sprint G security review verifies against a baseline instead of inventing one at the end. **P2**
18. **Bundle-size budget gate** — APTR-09 — Add a CI job with per-entry-chunk byte budgets and failure on regression; PWA and mobile performance die by a thousand cuts otherwise, and Sprint G "perf budgets" is too late to establish the baseline. **P2**
19. **Repo governance files** — APTR-04 — Add `LICENSE`, `SECURITY.md` (vuln reporting path for the public mirror), `CONTRIBUTING.md`, and `CODEOWNERS`. The README item ships a public-facing repo with none of them. **P2**
20. **License-compliance CI job** — APTR-09 — A dependency license allowlist gate. It's the mechanical twin of the no-vendoring rule: a "dependency" with an incompatible license is vendoring with extra steps. **P2**
21. **Request-size and JSON-shape limits in the contract** — APTR-06 — Global max body size, max JSON nesting depth, and max array lengths per route, so the BFF implements them uniformly and `payload-too-large` is testable. **P2**
22. **Message catalog from day one** — APTR-01 — Externalize user-facing strings into a typed message catalog (even English-only). Retrofitting i18n across seven sprints of inline strings is a rewrite; establishing the pattern is an hour. **P3**
23. **CI concurrency cancellation** — APTR-09 — Cancel superseded runs per-branch; keeps the no-retry policy on gating jobs affordable. **P3**
24. **Brand SVG sanitization check** — APTR-04 — Extend the SVG validation to reject `<script>`, `<foreignObject>`, and event-handler attributes in `assets/`; these files render on the public mirror. **P3**
25. **Uninstall/rollback section** — APTR-14 — Add "Removing Aperture" (disabling the cargo feature, revoking sessions, clearing PWA caches/service worker) and a rollback note for a bad deploy. Sovereignty includes clean exit. **P3**

## DEFECTS

- **APTR-01** — `assert-no-external-hosts.mjs` as specified will fail every clean build: bundled inline SVG carries `xmlns="http://www.w3.org/2000/svg"`, and license banners commonly contain URLs. The script needs a documented allowlist of XML namespace URIs and comment-stripped scanning, or the acceptance criterion "build fails when any external origin appears" is unmeetable alongside "clean build passes." The negative test as written would appear to work while the positive path is broken.
- **APTR-07** — "Never construct an absolute URL" conflicts with the Sprint E Tauri target (see Enhancement 3). As written, the Sprint A acceptance criterion must be violated by Sprint E or Sprint E cannot reach the backend.
- **APTR-08** — Descriptor revalidation "on the SSE `context` channel" depends on Sprint B's stream, but A blocks B and nothing marks this forward dependency. Add a polling fallback in A and an explicit note that SSE revalidation lands in B, or the item is untestable as specified.
- **APTR-06** — The auth route group is listed with zero session/CSRF semantics (Defect twin of Enhancements 1–2). For a "document every later sprint codes against," omitting the security-critical half of auth is the contract-first failure mode this item exists to prevent.
- **APTR-11** — "Fall back to cached vault values, never hard-fail" specifies no cache location, protection, or staleness bound; as written an agent could satisfy it by writing plaintext secrets to disk.
- **APTR-05** — The two-PR cross-repo split is fine, but the Aperture-repo PR's test plan cannot exercise any of the item's acceptance criteria (they all live in agent-core). State explicitly which repo's gate proves which criterion, or the Aperture PR merges "green" proving nothing.

## MISSING

- **Any CSP/security-header item.** The sprint's only clause-6 enforcement is a grep over the bundle; runtime egress and script-injection enforcement is absent entirely.
- **Client/BFF version-skew and PWA cache-invalidation story** — no item owns what happens when a cached bundle meets a newer BFF.
- **First-account bootstrap semantics** — APTR-14 mentions "creating the first account" but no contract route or trust model for the zero-users state exists in APTR-06's auth group.
- **Deep-link contract** — Sprint E registers deep links, but the URL scheme and its validation rules (unsafe deep links are a named review criterion) aren't reserved in the v1 contract, guaranteeing churn.
- **E2E scaffold** — Playwright (or equivalent, self-hosted) appears only in Sprint G; standing up the harness in A lets C–F ship e2e tests with their features instead of retroactively.
- **LICENSE / SECURITY.md / CONTRIBUTING** for a repo that ships to a public mirror in this very sprint (APTR-13).
- **Empty/loading/skeleton state primitives** — the design-system item covers cards, buttons, badges, and tables but no skeleton, spinner, empty-state, or progress vocabulary, which every later sprint needs on day one.
- **Time/locale conventions** — no statement that all API timestamps are UTC ISO-8601 and rendering is client-local; a classic cross-sprint inconsistency source.
